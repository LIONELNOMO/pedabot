I. La Boucle POUR — Répétition à nombre fixe

PATTERN 26 — BOUCLE_POUR

La syntaxe de la boucle POUR s'écrit de la manière suivante en algorithmique :

POUR i DE 1 À N FAIRE
    <instructions>
FIN POUR

On utilise la boucle POUR lorsque le nombre de répétitions est connu à l'avance. La variable de contrôle i est incrémentée automatiquement à chaque tour de boucle.

Voici un exemple concret d'utilisation de la boucle POUR :

POUR i DE 1 À 10 FAIRE
    Écrire(i)
FIN POUR

En Python, cette même boucle s'écrit avec for i in range(1, 11):. En JavaScript, on utilise for (let i = 1; i <= 10; i++).

Exemples de phrases déclencheuses

La boucle POUR permet de répéter un bloc d'instructions un nombre défini de fois.

La syntaxe POUR i DE 1 À N FAIRE est utilisée quand le compteur est connu dès le départ.

On écrit une boucle for en Python avec for i in range(n): pour parcourir N éléments.

La structure for (let i = 0; i < n; i++) est la syntaxe JavaScript de la boucle à compteur.

II. La Boucle TANT QUE — Répétition conditionnelle

PATTERN 27 — BOUCLE_TANTQUE

La structure TANT QUE est une boucle dont la condition est évaluée avant chaque itération. Si la condition est fausse dès le départ, le corps n'est jamais exécuté.

TANT QUE condition FAIRE
    <instructions>
FIN TANT QUE

En Python, la boucle TANT QUE s'écrit avec le mot-clé while :

while condition:
    instructions

L'inconvénient principal de la boucle TANT QUE est le risque de boucle infinie si la condition n'est jamais rendue fausse à l'intérieur du corps.

— TANT QUE ... FAIRE / FIN TANT QUE
— while condition:

— Titre de section contenant : "tant que", "while", "boucle conditionnelle", "répétition conditionnelle"

Exemples de phrases déclencheuses

La boucle TANT QUE répète les instructions tant que la condition reste vraie.

On utilise while n != 0: pour continuer la saisie jusqu'à ce que l'utilisateur entre 0.

La syntaxe TANT QUE réponse != 'oui' FAIRE permet d'attendre une réponse valide.

En JavaScript, while (x > 0) continue tant que x est positif.

III. La Boucle RÉPÉTER JUSQU'À — Exécution garantie

PATTERN 28 — BOUCLE_REPETER

La boucle RÉPÉTER JUSQU'À garantit qu'au moins une exécution du corps aura lieu, car la condition d'arrêt est évaluée après chaque itération.

RÉPÉTER
    <instructions>
JUSQU'À condition_arrêt

En JavaScript, l'équivalent est la boucle do...while :

do {
    instructions;
} while (condition);

On utilise RÉPÉTER JUSQU'À principalement pour la validation de saisie utilisateur, car on doit toujours afficher le message au moins une fois avant de vérifier la valeur entrée.

— Titre de section contenant : "répéter jusqu'à", "do while", "boucle post-condition"

Exemples de phrases déclencheuses

La boucle RÉPÉTER JUSQU'À exécute le corps au moins une fois avant de tester la condition.

On utilise RÉPÉTER ... JUSQU'À n > 0 pour forcer l'utilisateur à saisir une valeur positive.

La syntaxe do { ... } while (choix != 0) est idéale pour un menu interactif en JavaScript.

IV. L'Alternative SI / SINON — Prise de décision

PATTERN 29 — ALTERNATIVE_SI

La structure conditionnelle SI/SINON permet de choisir entre deux blocs d'instructions selon qu'une condition est vraie ou fausse.

SI condition ALORS
    <bloc si vrai>
SINON
    <bloc si faux>
FIN SI

On peut aussi imbriquer des conditions avec SINON SI pour gérer plusieurs cas :

SI note >= 16 ALORS
    Écrire("Très bien")
SINON SI note >= 10 ALORS
    Écrire("Passable")
SINON
    Écrire("Insuffisant")
FIN SI

En Python, cela s'écrit avec if, elif et else. En JavaScript, on utilise if (...) { } else if (...) { } else { }.

— if ... elif ... else
— if (...) { } else { }

Exemples de phrases déclencheuses

La structure SI condition ALORS ... SINON ... FIN SI permet d'exécuter deux blocs différents.

On utilise if note >= 10: pour afficher "Admis" et else: pour afficher "Échec".

L'alternative if (x % 2 == 0) permet de tester si un nombre est pair ou impair en JavaScript.

Avec SINON SI, on peut gérer plusieurs cas : très bien, bien, passable, insuffisant.

V. Les Fonctions et Procédures — Modularité

PATTERN 30 — DECLARATION_FONCTION

Une fonction est un sous-programme qui retourne une valeur. Une procédure est un sous-programme qui effectue des actions sans retourner de valeur.

La syntaxe d'une fonction en algorithmique est la suivante :

FONCTION nomFonction(paramètre1 : Type, paramètre2 : Type) : TypeRetour
    VARIABLE résultat : TypeRetour
    DÉBUT
        <instructions>
        RETOURNER résultat
    FIN

En Python, on déclare une fonction avec le mot-clé def :

def nom_fonction(param1, param2):
    # instructions
    return résultat

En JavaScript, la déclaration utilise le mot-clé function :

function nomFonction(param1, param2) {
    // instructions
    return résultat;
}

VI. Les Tableaux — Structures de Données Indexées

PATTERN 31 — TABLEAU_ARRAY

Un tableau est une structure de données permettant de stocker plusieurs valeurs du même type accessibles par un indice (ou index).

La déclaration d'un tableau en algorithmique :

VARIABLE notes : TABLEAU[0..N-1] DE Réel

Pour parcourir tous les éléments d'un tableau, on combine tableau et boucle POUR :

POUR i DE 0 À N-1 FAIRE
    Écrire(notes[i])
FIN POUR

En Python, un tableau s'appelle une liste et se déclare ainsi :

notes = []          # liste vide
notes = [0] * N     # liste de N zéros
notes.append(val)   # ajouter un élément

En JavaScript, on utilise la syntaxe :

let notes = [];
let notes = new Array(N);
notes.push(val);

Exemples de phrases déclencheuses

Un tableau se déclare avec VARIABLE T : TABLEAU[0..9] DE Entier pour stocker 10 entiers.

On accède à l'élément d'indice i avec la notation T[i].

En Python, on crée une liste de 5 zéros avec notes = [0] * 5.

Le parcours d'un tableau se fait en combinant POUR i DE 0 À N-1 FAIRE avec Écrire(T[i]).

En JavaScript, let scores = new Array(10) crée un tableau de 10 cases.

VII. Comparaison et Contraste entre Concepts

PATTERN 32 — COMPARAISON

On compare deux structures selon leur mode de fonctionnement. La boucle POUR s'utilise quand le nombre d'itérations est connu à l'avance, tandis que la boucle TANT QUE s'utilise quand ce nombre dépend d'une condition.

Contrairement à la boucle TANT QUE qui peut ne jamais s'exécuter, la boucle RÉPÉTER JUSQU'À garantit au moins une exécution du corps.

Une fonction retourne une valeur, à l'opposé d'une procédure qui effectue une action sans retourner de résultat.

Le passage par valeur copie la donnée, par opposition au passage par référence qui transmet directement l'adresse mémoire de la variable.

Comparé à un algorithme de tri en O(n²), le tri rapide est bien plus efficace avec une complexité en O(n log n) en moyenne.

Le tableau est statique, par opposition à la liste dynamique qui peut grandir.

VIII. Erreurs Fréquentes et Pièges à Éviter

PATTERN 33 — ERREUR_PIEGE

Une erreur courante est d'oublier d'initialiser la variable de contrôle avant une boucle TANT QUE, ce qui produit un comportement imprévisible au premier tour.

Attention à ne pas confondre l'opérateur d'affectation ← avec l'opérateur de comparaison =. Cette erreur typique provoque des bugs difficiles à détecter.

Un piège fréquent chez les débutants est d'écrire POUR i DE 1 À N au lieu de POUR i DE 0 À N-1 pour parcourir un tableau de taille N, causant un dépassement d'indice.

Ne pas confondre les paramètres formels (dans la signature) et les paramètres effectifs (lors de l'appel) est une erreur à éviter absolument pour comprendre le passage de paramètres.

Une faute courante avec la récursivité est d'oublier le cas de base, ce qui conduit à un appel infini et un débordement de pile.

Une erreur courante est d'utiliser = au lieu de == pour tester l'égalité.

IX. Trace d'Exécution et Suivi de Variables

PATTERN 34 — TRACE_EXECUTION

Pour comprendre une boucle, on peut construire un tableau de trace qui suit l'évolution des variables à chaque itération.

Lors du déroulement pas à pas de l'algorithme suivant, on observe comment la variable somme évolue :

i = 1 : somme = 0 + 1 = 1
i = 2 : somme = 1 + 2 = 3
i = 3 : somme = 3 + 3 = 6

À l'itération 3, la valeur de somme vaut 6. Ce type de trace d'exécution permet de vérifier qu'un algorithme produit bien le résultat attendu.

Les valeurs successives de la variable i dans une boucle POUR i DE 1 À 5 sont : 1, 2, 3, 4, 5. Après exécution, la variable i vaut 6 (dernière valeur tentée).

L'état du programme après chaque instruction peut être représenté dans un tableau avec une colonne par variable et une ligne par étape.

X. Entrées et Sorties d'un Algorithme

PATTERN 35 — ENTREE_SORTIE

Tout algorithme ou fonction peut être décrit par son contrat d'interface : ce qu'il prend en entrée et ce qu'il retourne en sortie.

La fonction Moyenne prend en entrée un tableau de réels et un entier N, et retourne en sortie un réel correspondant à la moyenne calculée.

Entrée  : notes (Tableau de Réel), N (Entier)
Sortie  : moyenne (Réel)

Les données d'entrée d'un algorithme de tri sont un tableau non ordonné. La valeur retournée est ce même tableau trié dans l'ordre croissant.

Lorsque la fonction ne retourne aucune valeur (procédure), on note Sortie : aucune ou on utilise le type VOID.

XI. Préconditions et Postconditions

PATTERN 36 — PRECONDITION

Une précondition est une condition que les données d'entrée doivent respecter pour que l'algorithme produise un résultat correct.

La fonction Division(a, b) garantit un résultat correct à condition que b ≠ 0. Si cette précondition n'est pas respectée, le résultat est indéfini.

La fonction RacineCarre(n) impose comme précondition que n ≥ 0, car la racine carrée d'un nombre négatif n'est pas définie dans les réels.

Une postcondition décrit ce que l'algorithme garantit que le résultat vérifie après son exécution. Par exemple : "le tableau retourné est trié dans l'ordre croissant".

Le contrat d'une fonction est l'ensemble de ses préconditions et postconditions. Sous réserve que les préconditions soient vérifiées, les postconditions sont garanties.

La précondition de TriRapide est que le tableau ne soit pas vide (N > 0).

XIII. Complexité et Efficacité des Algorithmes

PATTERN 38 — COMPLEXITE

La complexité algorithmique mesure le coût d'un algorithme en temps ou en mémoire en fonction de la taille N des données traitées.

Un algorithme avec deux boucles imbriquées sur N éléments a une complexité O(n²). C'est bien moins efficace que un algorithme en O(n log n) pour de grandes valeurs de N.

La recherche séquentielle dans un tableau non trié a une complexité en temps de O(n) car dans le pire cas on parcourt tous les éléments.

Le tri par sélection est moins efficace que le tri rapide pour des tableaux de grande taille, car son nombre d'opérations croît en O(n²) contre O(n log n) en moyenne pour le tri rapide.

Un algorithme est dit optimal quand aucun autre algorithme ne peut résoudre le même problème avec un coût en mémoire ou en temps moindre.

Exemples de phrases déclencheuses

La recherche dichotomique a une complexité O(log n), bien meilleure que la recherche linéaire en O(n).

Cet algorithme est plus efficace que le précédent car il évite les comparaisons redondantes.

Le nombre d'opérations d'un tri à bulles est proportionnel à n².

Un tableau trié permet une recherche en O(log n) au lieu de O(n), ce qui est plus optimal.

XIV. Règles Absolues et Principes Fondamentaux

PATTERN 39 — REGLE_ABSOLUE

Il faut toujours initialiser une variable avant de l'utiliser dans un calcul. Ne pas le faire est une source d'erreurs imprévisibles selon le langage utilisé.

On ne doit jamais modifier l'indice d'une boucle POUR à l'intérieur de son corps, car cela perturbe le mécanisme automatique d'incrémentation.

Le principe fondamental de la modularité stipule qu'une fonction ne doit faire qu'une seule chose et la faire bien — règle aussi appelée principe de responsabilité unique.

Toujours vérifier qu'un diviseur est non nul avant d'effectuer une division est une règle de bonne pratique qui évite les erreurs d'exécution fatales.

La règle d'or de la récursivité est : toute fonction récursive doit posséder un cas de base atteignable qui arrête les appels récursifs.

— il faut toujours, on ne doit jamais, ne jamais
— principe fondamental, règle d'or, règle de base
— toujours vérifier / initialiser / s'assurer, interdit de

Exemples de phrases déclencheuses

Il faut toujours fermer une boucle avec son mot-clé de fin (FIN POUR, FIN TANT QUE).

On ne doit jamais supposer qu'une variable est automatiquement initialisée à zéro.

Le principe fondamental des boucles est que la condition doit finir par devenir fausse.

Toujours s'assurer que l'indice de tableau est compris entre 0 et N-1 inclus.
